# Dual-mode release preparation

Prepared locally on **2026-11-05** for plugin **0.2.0** and engine **0.4.0**. This records the local preparation snapshot before beta publication. The stable Community listing remains unchanged; [GitHub releases](https://github.com/tattorba87/obsidian-edge-voice/releases) records current beta availability. Use this checklist with [CONTRIBUTING.md](../CONTRIBUTING.md#releases), not as authorization to publish.

## What is prepared

- Opt-in English microphone dictation, live/final text, shared player layout, input-driven mic/status feedback, mode exclusion, separate symbolic/custom shortcuts with conflict checks, optional sounds, casing and inactivity timeout. Both mode shortcuts double-tap to start and single-tap to stop.
- Native Moonshine English Tiny/Small/Medium streaming models. MLX remains an optional TTS backend; no MLX STT claim.
- Explicit manual model setup with pinned revision/size/SHA-256, atomic verified downloads, offline verification before managed model parsing, retained MIT notice, list/check/path/remove commands and an advanced trusted custom-folder override. The real packaged-engine check caught and fixed a CDN 403 for Python's default User-Agent.
- Protocol 1 remains compatible with older TTS-only engines/plugins. Dictation probes `dictation-streaming-v1`; older engines receive manual update guidance before microphone capture. Existing settings/voices are retained and dictation remains disabled after migration. No automatic install/download or online update check.
- README, dictation/setup/upgrade/privacy/troubleshooting/security/contributor docs; separate copy-ready listing descriptions and gallery/upload instructions in [community-listing/](community-listing/README.md).
- Real-engine STT video/GIF in both themes, three STT gallery images and a completed-transcript image; two resized existing TTS gallery images; the requested purple v4 banner, preserving its chip/crystal. [Media credits and QA](media/README.md) and [recording metadata](media/dictation-recording.json) retain source/hash/timing evidence.
- [Model/runtime/media license audit](licenses.md), [Piper model-card inventory](piper-licenses.md), upstream ASR MIT notice in the package and source availability in engine third-party notices. Feynman recordings without an explicit reuse grant are excluded; the requested v4 banner is selected, with its public promotional use still needing a brand-guideline check.

## Remaining gates before an actual release

1. **Claude review:** review the final code/doc/media changes and this checklist. The ignored local plans retain implementation decisions, prior Claude fixes, rejected demo takes and changes of course. Review managed-file trust boundaries and engine migration carefully; do not approve from the demo alone.
2. **Human microphone acceptance:** grant/deny permission, real speech, device change/disconnect, long dictation, typing/undo/selection/navigation/blur, optional sounds, custom keys and conflicts, timeout/0, unload, and TTS before/after STT in both themes and Markdown editing modes. Automated tests route synthetic/file audio and do not establish physical microphone behavior. No person's microphone was opened for demo creation.
3. **Platform gate:** run the authorized full CI/Engine package matrix once before publication (macOS Intel and Apple silicon, Windows and Linux). Validate real Apple silicon STT latency and MLX TTS independently. These paid workflows were intentionally not started for local preparation. Windows on ARM and Flatpak/Snap remain explicitly unverified as documented.
4. **Licensing/source gate:** preserve ASR MIT and bundled-library notices/source links and media attribution. Do not bundle or advertise unrestricted use of Piper/G2P weights where source grants are unclear. Some Piper dataset terms are noncommercial; see the audit. The maintainer selected the purple v4 chip/crystal banner; confirm its promotional use against Obsidian's brand guidelines before publication. No Feynman audio without source-specific reuse permission.
5. **Engine first:** when publication is authorized, build and publish **engine-0.4.0** with all platform requirements, checksums, notices and attestations. Run the exact published setup/model commands and verify every requirements URL before the plugin can point users to them. The local README/setup now names 0.4.0; those URLs will not work until that engine is published. This is sequencing, not a completed upload.
6. **Plugin next:** after approved changes are committed/merged, finalize the Unreleased changelog for 0.2.0, verify manifest/package/versions agree and use the normal release process. Versions are staged locally already; `bun run release` commits/tags and was not invoked. Follow the release script's behavior carefully if a version-only commit would be empty. Do not bypass hooks or create a tag merely to test preparation.
7. **Directory gate and listing:** use [Review branch](https://docs.obsidian.md/community-directory/manage-entry) to preview current policy checks. The entry is already listed, but that does not pre-approve the new microphone behavior. After the release is available, verify permanent media/doc URLs and copy the [listing kit](community-listing/README.md); upload the five suggested 1200×800 desktop images and retain credits. Saving the listing is a separate public action.

The branch is prepared for review and local testing. Local passes do not justify claiming that manual microphone checks, the full platform matrix, directory review, external media links or publication have already passed.
